# Расходы проекта — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сущность «Расход» в проекте: план/факт (количество × цена), иерархические категории, согласование финансовым администратором, привязка к понёсшему мастеру, гриды расходов, учёт в сводке и балансах мастеров.

**Architecture:** Отдельная ветка сущностей `Expense`/`ExpenseCategory`/`ExpenseApproval` в `JoinRpg.DataModel` (EF6, SQL Server) по паттернам репозитория; бизнес-логика в `ExpenseService` (MS DI, права через `ProjectInfo.RequestMasterAccess`); UI — Blazor-острова в новом RCL `JoinRpg.Web.Finances`, встроенные в страницы портала, данные через typed HttpClient → `/webapi/*`-контроллеры.

**Tech Stack:** ASP.NET Core (MVC + Razor Pages), Blazor WebAssembly islands (WebAssemblyPrerendered), EF6 Code-First, Shouldly, bUnit.

**Spec:** [docs/superpowers/specs/2026-11-04-expense-design.md](../specs/2026-11-04-expense-design.md)

## Global Constraints

- Видимые пользователю строки — только на русском, только в Web-слое (`JoinRpg.Web.*` razor-компоненты, `JoinRpg.Portal`). Сервисный/DAL-слой — без UI-строк (нарушение помечать `TODO[Localize]`).
- Деньги: `int` в рублях (как `FinanceOperation.MoneyAmount`); количество — `int`.
- Без regex. Без Moq/NSubstitute — классические тесты, фейки в стиле существующих.
- DI: только Microsoft DI (`AddJoinDomainServices` в `src/JoinRpg.Services.Impl/Services.cs`, `AddJoinDal` в `src/JoinRpg.Dal.Impl/Registraton.cs`). Не Autofac, не `Services.GetTypes()`.
- Идентификаторы сущностей — `ExpenseIdentification`/`ExpenseCategoryIdentification` в `JoinRpg.DomainTypes` (`[TypedEntityId]`-record'ы, по образцу `CharacterIdentification`). Сущности DataModel в сигнатурах сервисов/webapi/UI не прокидываем — только идентификаторы и DTO.
- Write-репозитории не регистрировать в DI — запись только через `IUnitOfWork` (см. комментарий в `Registraton.cs:39-53`).
- Это **EF6** (`System.Data.Entity`), не EF Core: маппинг — data annotations + `MyDbContext.OnModelCreating`, аудит (CreatedAt/UpdatedAt/CreatedBy/UpdatedBy) проставляется вручную через `JoinRpg.Domain.EntityAudit` в сервисе.
- Коммиты: `git commit -m "..."` без `--edit`. Перед коммитом `dotnet format`.
- Миграция EF6 создаётся по [docs/ef-migrations.md](../../ef-migrations.md) (CLI-рецепт с `ef6.dll`, scratch-БД `joinrpg_scratch`); главный `.cs` миграции — file-scoped namespace без BOM; NOT NULL колонки — с `defaultValue`; `.Designer.cs`/`.resx` не править руками.
- `docs/db-schema.md` обновляется в том же PR (руками, см. [docs/db-schema-regenerate.md](../../db-schema-regenerate.md)).
- Интеграционные тесты локально не гонять (CI), кроме `DbSchemaDocumentationScenario` через `--filter` (см. Task 2).

## Review Focus

1. **Правка сбрасывает одобрение** — любая правка расхода (включая заполнение факта) переводит состояние из `Approved`/`Rejected` в `Proposed`. Пин: тесты в Task 5.
2. **Права на одобрение** — Approve/Reject доступны только с `Permission.CanManageMoney`; создавать/править — любому мастеру проекта. Пин: тесты в Task 5 + `[RequireMaster(Permission.CanManageMoney)]` в Task 10.
3. **Разрешение пути категории (find-or-create)** — сервис разбивает введённый путь через «\» на сегменты и для каждого ищет категорию среди детей текущего уровня (сравнение имён без учёта регистра), создавая отсутствующие; итог — `CategoryId` листа и снапшот `CategoryPathImpl`. Пин: тесты в Task 5–6.
4. **Отклонённые расходы в сводке** — из итого остатка вычитается только `Approved`-факт; отклонённые и неодобренные не влияют на остаток. Пин: тест в Task 7 (билдер сводки).
5. **Балансы мастеров** — `MasterBalanceViewModel.Total` уменьшен на одобренный факт расходов понёсшего мастера (`ExpensesBalance`), план и неодобренное — отдельной колонкой `PlannedExpenses` (`ActualCost ?? PlannedCost` по неотклонённым, не входящим в `ExpensesBalance`; на `Total` не влияет). Пин: тесты в Task 7 (`MasterBalanceOverProjectInfoTest`).
