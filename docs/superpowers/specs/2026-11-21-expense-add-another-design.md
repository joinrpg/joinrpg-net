# Дизайн: «Продолжить добавлять расходы»

## Зачем

Мастера вносят расходы сериями (чек с несколькими позициями, закупка по одной статье).
Сейчас после сохранения диалог закрывается, и для каждой следующей позиции нужно заново
открывать форму и повторно заполнять одни и те же поля.

## Что делаем

На форме **добавления** (не редактирования) расхода — галочка «Продолжить добавлять расходы».
Если она установлена, после успешного сохранения диалог открывается снова, предзаполненный
частично данными из свежедобавленного расхода. Выход из режима — снять галочку или закрыть
диалог (отмена).

## Подходы

1. **Галочка в диалоге создания** (выбрано — так запросил пользователь). Пользователь видит
   режим до сохранения и может его снять; не нужен второй submit-кнопкой.
2. Отдельная кнопка «Сохранить и добавить ещё» — отклонено: кнопок становится две, а режим
   всё равно приходилось бы дублировать галочкой, если пользователь передумал после клика.

## Предзаполнение при повторном показе

| Поле | Что делаем | Почему |
|------|-----------|--------|
| Мастер | Копируем | Почти всегда тот же человек тратит подряд |
| Категория | Копируем | Типичный сценарий «закупка по одной статье» |
| Дата | Копируем | Та же поездка/чек; совпадает с текущим дефолтом страницы (дата последнего расхода) |
| Название | Очищаем | Обязательное поле; старое значение провоцирует дубли |
| Описание | Очищаем | У каждой позиции своё |
| Количество (план) | Очищаем | Решено при обсуждении: цена/количество у каждой покупки свои |
| Цена (план) | Очищаем | — |
| Количество (факт) | Очищаем | — |
| Цена (факт) | Очищаем | — |

## Как строится

- Страница `ExpensesPage.razor` уже умеет переоткрывать диалог с той же моделью
  (`EditAsync`, цикл при ошибке сохранения). Продолжение по галочке — тот же цикл:
  после успешного `CreateExpense` собираем новую модель по таблице выше и зовём
  `ShowAsync` снова.
- Галочка живёт на странице (не в диалоге): только режим создания, состояние держится
  между показами в рамках сессии страницы, снятие галочки или отмена диалога выходят
  из цикла.
- Галочка не показывается при редактировании существующего расхода.
- Сообщения валидации не должны протекать между показами — модель создаётся заново
  (это уже гарантировано комментарием в `ExpenseEditDialog.razor`).

## Не цели

- Запоминание галочки между сессиями / в localStorage.
- «Сохранить и добавить ещё» как отдельная кнопка.
