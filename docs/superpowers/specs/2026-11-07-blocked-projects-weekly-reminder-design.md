# Дизайн: еженедельное напоминание мастерам заблокированных проектов

Дата: 2026-11-07. Статус: утверждён, реализован.

## Зачем

После утери прод-данных в октябре 2026 (DRP #5459, ADR023) часть проектов до сих пор в статусе
«Заблокирован» (`Project.IsBlocked`). Мастерам этих проектов нужно регулярно напоминать: определиться
с судьбой проекта — закрыть его или восстановить данные по инструкции. Напоминание — каждый вторник
по всем каналам уведомлений (решение пользователя: email + Telegram + веб, как обычное уведомление).

## Цели / не-цели

- Цель: раз в неделю (по вторникам, ~12:00 МСК) каждый действующий мастер каждого заблокированного
  проекта получает уведомление с текстом из заявки.
- Не-цель: снятие блокировки, автозакрытие, отписка от рассылки, отдельный вид уведомления в истории.
- Анти-цель: не трогать незаблокированные, архивные и закрытые проекты и снятых мастеров (ADR019/023).

## Текст уведомления

Заголовок — «{имя проекта}: проект заблокирован на время восстановления данных», шаблон:

> Добрый день, %recepient.name%! Ваш проект {имя проекта} все еще заблокирован после утери данных
> в октябре. Вам нужно определиться, что делать с вашим проектом. Если он вам больше не нужен,
> закройте его. Если нужен — воспользуйтесь инструкцией по восстановлению:
> https://docs.joinrpg.ru/recovery-2026.html. По любым вопросам пишите в https://joinrpg.ru/support

Одно уведомление **на проект** (решение пользователя): мастер трёх заблокированных проектов получит
три уведомления. Имя проекта подставляется интерполяцией в коде, обращение — плейсхолдер
`%recepient.name%`.

## Подход

Новая ежедневная джоба по паттерну ADR002, с фильтром по дню недели внутри (прецедент —
`AdvertisementJob`). Репозиторий **не расширяем**: список есть (`GetBlockedProjects()`), мастера и
имя — из `IProjectMetadataRepository.GetProjectMetadata()` (`ProjectInfo.Masters` — уже только
действующие мастера, ADR019 §5; снятые в `FormerMasters`), отправка — по образцу
`MasterEmailService.EmailProjectUnblocked`.

1. **`BlockedProjectsReminderJob`** (`src/JoinRpg.Services.Impl/Projects/`, рядом с
   `ProjectPerformCloseJob`), `IJob`, атрибут `[JobDelay(9)]` (09:00 UTC = 12:00 МСК).
2. На каждый запуск: если день по UTC — не вторник, выход с логом. Иначе —
   `projectRepository.GetBlockedProjects()` и по каждому:
   - `projectMetadataRepository.GetProjectMetadata(projectId)`;
   - если `metadata.ProjectStatus != ProjectLifecycleStatus.Blocked` — пропуск с логом
     (самоинвариант: у проекта с `IsBlocked` статус всегда `Blocked`, но проверка дешевле
     письма, отправленного не тому);
   - иначе — `masterEmailService.EmailProjectBlockedReminder(...)`.
3. **В `MasterEmailService`** — новый метод по образцу `EmailProjectStale`: тема
   «{ProjectName}: проект заблокирован на время восстановления данных», тело — текст из заявки,
   получатели — `metadata.Masters.Select(m => new NotificationRecepient(m))`, инициатор —
   `virtualUsersService.RobotUserId`, отправка — `QueueNotification` (все каналы; email-white-list
   учитывается автоматически), `NotificationClass.MasterProject` (существующее «письма мастерам»,
   новый enum не нужен), `EntityReference` — id проекта.
4. Отказоустойчивость: try/catch на проект (прецедент `FormerMastersBackfillJob`) — падение
   отправки по одному проекту не роняет остальные; следующий вторник досылает.

### Регистрация

`AddJob<BlockedProjectsReminderJob>()` в `AddJoinDomainServices` (`src/JoinRpg.Services.Impl/Services.cs`,
рядом с `ProjectPerformCloseJob`) — джоба internal в сборке сервисов, портал её не видит. Попадает
в расписание и на `/Admin/Jobs`, управляется стандартным конфигом `DailyJobs:Disabled`.

### Тесты

Юнит-тест в `JoinRpg.Services.Impl.Test`: фейки `IProjectRepository`/`IProjectMetadataRepository`/
`INotificationService` (как существующие в `Fakes/`) — во вторник по каждому заблокированному проекту
уходит `QueueNotification` с правильными получателями и текстом; не-вторник — ничего не уходит;
проект со статусом не `Blocked` пропускается; падение одного проекта не останавливает остальные.
Плюс verify-снапшот итогового текста письма (требование ADR003). Интеграционные тесты не трогаем (CI).

### Что не делаем

- Новые методы репозитория, миграции БД, правки ADR — не нужны.
- Агрегация писем по пользователю, настройка дня недели из конфига, отписка — осознанно не делаем
  (разовая мера на время инцидента, ADR023: «блокировку как постоянный механизм не проектируем»).
