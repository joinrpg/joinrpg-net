# ShowCounter для JoinTextArea / JoinMarkdownTextArea — дизайн

Дата: 2026-11-08

## Намерение

В полях с ограничением длины (анкеты, заявки, комментарии) пользователь не видит, сколько осталось, и узнаёт об ограничении только из ошибки валидации. Опция `ShowCounter` показывает «20/3000» мелким приглушённым текстом под полем во время набора.

## Цели

- Показывать текущую/максимальную длину под полем при наборе текста.
- Включение — явное (опция), только когда задана максимальная длина.

## Не-цели

- Изменение семантики `ValueChanged` (по-прежнему срабатывает на `change`, а не на каждый ввод).
- Изменение поведения существующих вызовов без новых параметров.
- `JoinTextInput` и другие компоненты — вне рамок.

## Подходы

1. **Читать `maxlength` из `AdditionalAttributes`** — без изменений API, но магия: счётчик молча зависит от прохождения атрибута через splat, невалидное значение атрибута ломает компонент.
2. **Явный параметр `MaxLength`** (выбран) — компонент сам рендерит `maxlength` и питает счётчик. Дублирует HTML-атрибут, зато проверяемо и типобезопасно.

## Решение (подход 2)

### JoinTextArea (`src/Common/WebComponents/JoinRpg.Common.WebComponents/JoinTextArea.razor`)

- Новый параметр `int? MaxLength` — при заданном значении рендерит `maxlength` на `<textarea>`.
- Новый параметр `bool ShowCounter` (по умолчанию `false`).
- Счётчик показывается, когда `ShowCounter && MaxLength.HasValue`: `<div class="text-muted small">{текущая}/{MaxLength}</div>` сразу под обёрткой поля.
- Текущая длина обновляется «вживую»: к существующему `@onchange` добавляется `@oninput`, обновляющий только счётчик (не `internalValue`, чтобы Blazor не перерисовывал содержимое `<textarea>` во время набора и не сдвигал каретку). Начальное значение — `Value.Length`.

### JoinMarkdownTextArea

- Параметры `MaxLength` и `ShowCounter` прокидываются внутрь `JoinTextArea`; счётчик выводится под полем, над подсказкой про Markdown (это решение за реализацию — другое расположение маловероятно).

### Мои решения (можно поправить)

- Обновление счётчика на каждый ввод (`@oninput`), а не только на `change`/потерю фокуса — иначе «при наборе текста» не выполняется.
- Если задан и параметр `MaxLength`, и атрибут `maxlength` через `AdditionalAttributes` — параметр выигрывает (атрибут splat'ится раньше).
- `ShowCounter` без `MaxLength` — счётчика нет (условие из запроса).
