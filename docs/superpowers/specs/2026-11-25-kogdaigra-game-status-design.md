# Статус игры с КогдаИгры: парсинг, хранение, показ в селекторе

## Зачем

КогдаИгра в `api/game/{id}` отдаёт числовой `status` и строку `status_name`,
мы их игнорируем (`ResultParser` их не читает). В проде 800 отменённых игр
числятся обычными активными и предлагаются к привязке наравне с живыми.
Задача — расшифровать статус, сохранить его и показывать в селекторе
привязки игр, чтобы мастер видел «Отменена»/«Отложена» до привязки.

## Цели

- Парсить `status` (int) из ответа КогдаИгры.
- Хранить код статуса в БД (`KogdaIgraGames`), с бэкфиллом из уже лежащего
  там `JsonGameData` (сырой JSON хранится с самого начала, перезагрузка
  с КогдаИгры не нужна).
- Расшифровывать код в русскую подпись у себя.
- Показывать подпись статуса в селекторе привязки (`KogdaIgraGameSelector`).

## Не-цели

- Фильтрация по статусу в выборках — отдельные фичи, сделает @leotsarev.
- Показ статуса в карточке игры (`KogdaIgraCard`) — отдельное issue.
- Показ статуса в админском списке (`KogdaIgraSyncList`) — отдельное issue.
- Флаг `Active` не трогаем: отменённые игры не деактивируются.

## Подходы

1. **Колонка с сырым кодом + enum-расшифровка у нас (выбрано).** В БД — `int?`
   со статусом как есть; маппинг код → русская подпись живёт в коде.
   Дешёвая миграция, бэкфилл одним SQL, фильтрация в будущем — обычный
   WHERE по колонке.
2. Парсить статус из `JsonGameData` на лету — отклонено: JSON_VALUE в LINQ
   не транслируется, пришлось бы материализовать выборки.
3. Хранить строку `status_name` — отклонено: дублирует код, а для кода 2
   бесполезна (КогдаИгра сама отдаёт «???»).

## Части

### Клиент (`JoinRpg.Common.KogdaIgraClient`, NuGet-пакет)

- В `kogda_igra_game_data` и `KogdaIgraGameInfo` добавить `int? Status`.
  `NumberHandling.AllowReadingFromString` уже включён — строковая форма
  (`"status":"1"`) разберётся.
- Публичный API меняется: `pwsh scripts/Update-PublicApi.ps1` + запись
  в «Не выпущено» `CHANGELOG.md` пакета.

### DataModel + миграция (EF6)

- `KogdaIgraGame.Status` — `int?`. Колонка nullable намеренно: NULL — это
  честное «мы статус не знаем», и оно отличается от кода 2 («КогдаИгра сама
  не знает статус игры»). NULL остаётся у:
  - ~1038 записей с `JsonGameData = "{}"` (удалённые игры — `DeleteItem`
    затирает JSON пустышкой — и старые placeholder-записи): бэкфиллу их
    заполнять нечего;
  - новых placeholder-записей «Загружается N» от `MarkUpdateRequested` до
    первого `GetGameInfo`.
  NOT NULL потребовал бы фиктивной заглушки (-1), которая та же NULL, но
  менее честная и с сюрпризом для фильтров.
- Миграция с бэкфиллом:
  `UPDATE KogdaIgraGames SET Status = CAST(JSON_VALUE(JsonGameData, '$.status') AS int)`
  (JSON_VALUE на проде доступен — проверено при разборе).

### Синк (`JoinRpg.Integrations.KogdaIgra`)

- `UpsertItem` сохраняет `kiData.Status` в запись.

### Расшифровка (`JoinRpg.DomainTypes`)

- Enum `KogdaIgraGameStatus`: `Ok = 0`, `Passed = 1`, `Unknown = 2`,
  `Postponed = 3`, `DateUncertain = 4`, `Cancelled = 5`.
- Расшифровка в русскую подпись: «OK», «Прошла», «Статус неизвестен»,
  «Отложена», «Дата уточняется», «Отменена». Незнакомые коды →
  «Статус N» (пробрасываем как есть, не падаем).

### Выборки и UI

- `KogdaIgraListItem` и `KogdaIgraShortViewModel` получают `KogdaIgraGameStatus? Status`;
  заполняется в репозитории из колонки, прокидывается менеджером.
- Подписи живут в UI-слое: хелпер `KogdaIgraStatusLabel` в `JoinRpg.Web.ProjectCommon`
  (подписи — пользовательские строки, по правилам локализации им место в UI-слое,
  а не в DomainTypes).
- `KogdaIgraGameSelector`: в subtext к году добавляется статус
  («2026 · Отменена»; без года — просто статус). Для OK и «Прошла» статус
  в селекторе не показываем — это норма, шум только от нестандартных
  статусов. (Моё решение, можно оспорить.)

### Тесты

- `GameDataParserTest`: парсинг `status` (число и строка), отсутствие поля.
- Маппинг код → подпись, включая неизвестный код.
