# Сводка по деньгам: минуса, ссылки, агрегация категорий

Дата: 2026-11-10
Статус: принято, реализовано (финальное ревью ветки: готово к мерджу)

## Зачем

На странице «Сводка по деньгам» (`/{projectId}/money/MoneySummary`, view
`src/JoinRpg.Portal/Views/Finances/MoneySummary.cshtml`) пять недочётов:

1. В таблице «Итого» расходы показаны положительными числами, хотя они уменьшают
   итог — читается двусмысленно.
2. Заголовок блока «Расходы» не ведёт на страницу расходов проекта.
3. Заголовок «По типам» неочевиден и не ведёт на список операций.
4. Суммы по категории расходов не включают подкатегории.
5. Категория, у которой есть расходы только в подкатегориях, не показывается.

## Подходы

Рассматривалось:

- **Категории:** (А) только корневые категории со свёрнутой суммой поддерева —
  короче, но теряет детализацию. (Б) всё дерево: каждая категория — строка,
  суммы включают её поддерево, дети — вложенно. **Выбрано Б** — детализация важнее
  длины таблицы.
- **Знак минус:** (А) только отображение на странице сводки. (Б) значения
  `ExpensesBalance`/`PlannedExpenses` отрицательные в `MasterBalanceViewModel`,
  знак минус везде, где эта таблица. **Выбрано Б** — согласованность между
  страницей сводки, страницей мастера (ByMaster) и CSV-выгрузкой SummaryByMaster.

## Изменения

### 1–2. Минус для расходов (`MasterBalanceViewModel`)

`src/JoinRpg.WebPortal.Models/Money/MasterBalanceViewModel.cs`:

- `ExpensesBalance = -ownExpenses.Sum(e => e.ActualBalanceEffect)`,
  `PlannedExpenses = -ownExpenses.Sum(e => e.PlannedBalanceEffect)` — оба
  отрицательные.
- `Total = FeeBalance + ReceiveBalance + SendBalance + ExpensesBalance`
  (раньше вычитался модуль).

Это затрагивает: таблицу «Итого» и страницу ByMaster (partial `_MasterBalance.cshtml`
менять не нужно — он рисует значения как есть), и CSV-выгрузку `SummaryByMaster`
(значения станут отрицательными — сознательное ломающее изменение формата выгрузки,
выбрано пользователем).

### 3. Заголовок «Расходы» со ссылкой

`ExpenseSummaryTable.razor` получает новый параметр `ProjectId`; заголовок
`Расходы (подробнее)` со ссылкой на `/{projectId}/money/expenses` (роут страницы
расходов после #6206; в момент написания спеки был `/{projectId}/expenses`). Вызов в
`MoneySummary.cshtml` передаёт `Model.ProjectId`.

### 4. Заголовок «Взносы» со ссылкой

В `MoneySummary.cshtml` заголовок `По типам` → `Взносы`, добавляется ссылка
`(подробнее)` на `/{projectId}/money/operations`.

### 5–6. Агрегация категорий (`ExpenseSummaryBuilder`)

`src/JoinRpg.WebPortal.Models/Money/ExpenseSummaryViewModel.cs`:

- Группировка не по строке-пути, а по каждому узлу пути: расход учитывается во
  всех категориях своего пути (себя и всех предков).
- Строка показывается для каждой категории, у которой суммы по поддереву не нулевые
  (в т.ч. категории без собственных прямых расходов).
- Строки сортируются по пути; дочерние категории выводятся сразу после родителя
  (лексикографическая сортировка по пути это даёт).
- `TotalSpent` не меняется — по-прежнему сумма по всем расходам без двойного счёта.
- Последней строкой таблицы идёт «Итого» (жирным): суммы по колонкам, посчитанные
  по расходам напрямую, а не суммой строк — иначе агрегация подкатегорий дала бы
  двойной счёт.

Порядок полей строки (`CategoryPath`, три суммы) не меняется; `ExpenseSummaryTable.razor`
и его вызов продолжают работать без изменения модели строки.
