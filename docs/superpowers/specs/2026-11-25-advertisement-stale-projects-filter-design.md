# Фильтр неактивных проектов в рекламе — дизайн

## Зачем

В рекламу (горячие роли и дайджест) попадают проекты, которые мастера давно не обновляли, —
рекламировать мёртвые игры бессмысленно. Нужно исключать проекты, не обновлявшиеся последние
две недели.

## Что есть сейчас

- Кандидаты: `GetPublicProjectsOpenForHotRoleAdvertisement` и
  `GetPublicProjectsOpenedForClaimsInLastWeek` (`src/JoinRpg.Dal.Impl/Repositories/ProjectRepository.cs`).
  Фильтра по дате обновления нет.
- Дата последнего обновления проекта уже считается: `GetProjectWithLastUpdateQuery`
  (ProjectRepository.cs:203) — максимум по комментариям, персонажам, группам, сюжету, заявкам.

## Подход

Отклонённые альтернативы:

- Фильтровать по «мастерской» активности (без заявок и комментариев игроков) — точнее отражает
  «мастера забросили игру», но требует отдельного запроса; отклонено пользователем в пользу
  существующего `LastUpdated`.
- Фильтровать в `AdvertisementJob` после выборки — потребовало бы догружать дату обновления
  отдельно; дешевле отфильтровать в SQL тем же join'ом, что уже используется в
  `GetProjectListInternal` / `GetKogdaIgraMissingGames`.

Выбрано: в обоих методах-источниках кандидатов добавить join на `GetProjectWithLastUpdateQuery()`
и условие `update.LastUpdated >= DateTime.UtcNow.AddDays(-14)` (константа в репозитории).
Inner join безопасен: проект без единой записи обновления (нет даже персонажей) кандидатом
быть не может — для горячих ролей нужны персонажи, для дайджеста — открытые заявки.

Дайджест (`...OpenedForClaimsInLastWeek`) фильтруем тем же условием для единообразия:
`ClaimsOpenedDate` не входит в `LastUpdated`, поэтому проект формально может быть «свежим»
по дайджесту (открыл заявки неделю назад) и «старым» по обновлениям. Единый фильтр закрывает
и этот случай.

## Тесты

- Интеграционный сценарий `AdvertisementProjectRankingScenario` — добавить проект с горячими
  ролями, но без обновлений за последние 2 недели, и проверить, что он не попадает
  в кандидаты (обе выборки). Прогон — в CI (AGENTS.md: интеграционные тесты локально не гонять).
- Юнит-тесты предикатов (`ProjectPredicatesTest`) не трогаем: фильтр — join в репозитории,
  а не предикат.
