# Кнопка «Добавить расход» на сводке по деньгам

Дата: 2026-11-21
Статус: принято (пересмотрено после ревью: вместо WASM-острова — ссылка
на страницу расходов с автоматическим открытием диалога)

## Зачем

На странице «Сводка по деньгам» (`/{projectId}/money/moneysummary`, view
`src/Web/JoinRpg.Portal/Views/Finances/MoneySummary.cshtml`) мастеру часто нужно
быстро внести расход, не уходя со сводки. Сейчас приходится открывать страницу
расходов (`/{projectId}/money/expenses`).

## Цель

Кнопка добавления расхода в строке заголовка «Расходы», открывающая диалог
создания. Диалог — существующий `ExpenseEditDialog`
(`src/JoinRpg.Web.Finances/Expenses/ExpenseEditDialog.razor`).

## Не цели

- Обновление таблиц сводки без перезагрузки страницы.
- Правка/согласование расходов со сводки (остаётся на странице расходов).
- Изменение бизнес-правил расходов (ADR030).

## Подход

**Выбрано: статическая кнопка-ссылка `?create=1` по аналогии с кнопкой
«Отметить перевод» на той же странице.** Кнопка ведёт на страницу расходов
с параметром `create`, а `ExpensesPage` после загрузки открывает диалог
создания сама. Отдельный интерактивный компонент на сводке не нужен.

Преимущества над WASM-островом (рассматривался и был реализован в первой
версии PR, потом удалён по ревью):

- ноль дублирования: цикл диалога, предзаполнение, обработка ошибок и
  «Продолжить добавлять расходы» остаются только в `ExpensesPage`;
- сводка остаётся полностью статической — не грузится Blazor WASM-бандл
  ради одной кнопки;
- разметка кнопки — тот же `<component type="typeof(JoinButton)"
  render-mode="Static">`, что у переводов.

Недостаток: диалог открывается на странице расходов, а не «тут же» на сводке.
Сознательно принято, как и для переводов (кнопка ведёт на отдельную страницу).

## Изменения

### Кнопка на сводке

`MoneySummary.cshtml`: заголовок «Расходы» переезжает из `ExpenseSummaryTable`
на страницу (как сделаны заголовки «Взносы» и «Переводы») и обрастает
статической `JoinButton`:

- ссылка «подробнее» — через `IExpensesUriLocator.GetExpensesUri` (локатор,
  а не хардкод маршрута);
- кнопка «Новый расход» — `Link = GetExpensesUri(...) + "?create=1"`,
  `Preset=Add`, `Style=Success` (по аналогии с «Отметить перевод»).

Из `ExpenseSummaryTable` убираются `h3` и инъекция `IExpensesUriLocator`,
параметр `ProjectId` больше не нужен.

### Автооткрытие диалога в `ExpensesPage`

`src/Web/JoinRpg.Blazor.Client/Expenses/ExpensesPage.razor`:

- при инициализации читается query-параметр `create` (без regex и без
  `QueryHelpers` — его нет в BlazorWebAssembly SDK; ручной разбор `a=b&...`);
- когда диалог впервые появляется в разметке (при живой загрузке первые рендеры
  — JoinLoadingMessage, `@ref` ещё null) вызывается существующий `StartCreate()` —
  с теми же дефолтами, что и кнопка «Новый расход» на самой странице;
- после закрытия диалога параметр убирается из адресной строки напрямую через
  `history.replaceState` (JS interop): остров без Blazor Router, а
  `NavigationManager.NavigateTo` в таком приложении делает полную перезагрузку
  страницы (замерено, ADR027 §5). Так F5 не открывает диалог заново.

### Тесты

- `ExpensesPageTest`: `?create=1` открывает диалог без клика, после отмены
  адрес очищается от параметра.
- `ExpenseSummaryTableTest`: заголовка больше нет, параметр `ProjectId`
  удалён.

Отдельный компонент `AddExpenseWidget` и его тесты из первой версии PR
удалены.
