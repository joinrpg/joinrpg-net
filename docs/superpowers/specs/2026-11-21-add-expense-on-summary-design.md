# Кнопка «Добавить расход» на сводке по деньгам

Дата: 2026-11-21
Статус: принято

## Зачем

На странице «Сводка по деньгам» (`/{projectId}/money/moneysummary`, view
`src/Web/JoinRpg.Portal/Views/Finances/MoneySummary.cshtml`) мастеру часто нужно
быстро внести расход, не уходя со сводки. Сейчас приходится открывать страницу
расходов (`/{projectId}/money/expenses`).

## Цель

Кнопка добавления расхода в строке заголовка «Расходы», открывающая диалог
создания прямо на сводке. Диалог — существующий `ExpenseEditDialog`
(`src/JoinRpg.Web.Finances/Expenses/ExpenseEditDialog.razor`).

## Не цели

- Обновление таблиц сводки без перезагрузки страницы.
- Правка/согласование расходов со сводки (остаётся на странице расходов).
- Изменение бизнес-правил расходов (ADR030).

## Подход

**Выбрано: минимальный WASM-остров.** Статическая таблица сводки не меняет
режима рендеринга; рядом с заголовком «Расходы» рендерится маленький
интерактивный компонент (кнопка + диалог + сохранение). После успешного
сохранения — перезагрузка страницы, статические таблицы обновляются из БД.

Рассматривался остров вокруг всей секции «Расходы» (загрузка сводки через новый
JSON-endpoint, обновление без перезагрузки) — отклонён: заметно больше кода
(новый endpoint, дублирование разметки таблицы на острове) ради устранения
одного мигания перезагрузки.

## Изменения

### Новый компонент `AddExpenseWidget.razor`

`src/JoinRpg.Blazor.Client/Expenses/AddExpenseWidget.razor` — рядом с `ExpensesPage`:
`IExpensesClient` зарегистрирован DI только в WASM-клиенте, общая RCL
`JoinRpg.Web.Finances` его не видит.

- `JoinButton` Preset=Add, label «Новый расход» (как на странице расходов),
  открывает `ExpenseEditDialog`.
- При инициализации грузит `IExpensesClient.GetCurrentUser` (мастер по
  умолчанию) и `GetCategoryPathSuggestions` (подсказки категорий).
- Дефолты модели: `MasterId` = текущий пользователь, `SpentAt` = сегодня
  (мой вызов: страница расходов берёт дату последнего расхода, но виджет не
  грузит список ради одной даты).
- Сохранение: `Client.CreateExpense`; при успехе — полная перезагрузка
  (`NavigationManager.NavigateTo(uri, forceLoad: true)`); при
  `ServerProblemException` — `JoinAlert` с текстом ошибки, страница не
  перезагружается. Логика «показать снова с введёнными данными при отказе
  сервиса» копируется с `ExpensesPage.EditAsync` (без потери ввода).

### «Продолжить добавлять расходы»

В диалоге уже есть галочка «Продолжить добавлять расходы» (`AddAnother` на
`ExpenseEditDialog`, спека `2026-11-21-expense-add-another-design.md`, PR #6257) —
при создании показывается всегда. Виджет биндит `@bind-AddAnother` и реализует
тот же цикл, что `ExpensesPage.EditAsync(isCreate: true)`:

- сохранение удалось, галочка стоит — диалог открывается заново с новой моделью,
  предзаполненной из сохранённого расхода: мастер, категория и дата повторяются,
  название/описание/суммы пустые;
- сохранение удалось, галочка снята — перезагрузка страницы;
- отмена — если за сессию сохранён хотя бы один расход, перезагрузка страницы
  (статические таблицы обновляются); если ни одного — просто закрытие.
- Кнопка видна всем мастерам, видящим страницу; права проверяет сервер
  (как «Новый расход» на странице расходов).

### Заголовок «Расходы» переезжает из компонента на страницу

`h3` «Расходы (подробнее)» сейчас внутри `ExpenseSummaryTable.razor` (статический
компонент не может вместить интерактивную кнопку). Переносим его в
`MoneySummary.cshtml` — как сделаны заголовки «Взносы» и «Переводы»:

- `MoneySummary.cshtml`: `<h3>Расходы (<a …>подробнее</a>) [AddExpenseWidget]</h3>`,
  далее статический `ExpenseSummaryTable` без собственного заголовка.
- Ссылка «подробнее» на Razor Page расходов (`/GamePages/Expenses`,
  роут `/{projectId:int}/money/expenses`).
- Из `ExpenseSummaryTable` убираются `h3` и инъекция `IExpensesUriLocator`,
  параметр `ProjectId` больше не нужен.

### Тесты

- Новый bUnit-тест виджета (проект `JoinRpg.Blazor.Client.Test`): кнопка
  открывает диалог; отмена ничего не сохраняет; submit вызывает
  `CreateExpense` и перезагрузку (заглушить `NavigationManager`); с галочкой
  «Продолжить добавлять расходы» после сохранения диалог открывается заново
  с предзаполненной моделью, отмена после сохранённого расхода ведёт к
  перезагрузке.
- Обновить `ExpenseSummaryTableTest`: заголовка больше нет, параметр
  `ProjectId` удалён.
