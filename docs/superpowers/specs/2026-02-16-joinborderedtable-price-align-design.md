# JoinBorderedTable: выравнивание ячеек с ценой по правому краю

Дата: 2026-02-16
Статус: предложено

## Зачем

В таблицах на базе `JoinBorderedTable` (расходы, финансы и т.д.) ячейки с суммами
сейчас выравниваются по левому краю, как обычный текст. Деньги принято выравнивать
по правому краю — так проще сравнивать суммы в столбце.

## Цель

Если ячейка (`<td>`) внутри `JoinBorderedTable` содержит компонент `PriceElement`
(рендерит `<span class="price-value price-RUR">`), ячейка выравнивается по правому
краю автоматически, без правок в местах использования.

## Не-цели

- Изменение `PriceElement` или разметки в вызывающих компонентах (`ExpensesGrid`,
  `ExpenseSummaryTable` и пр.).
- Выравнивание шапок столбцов (`<th>`) — шапка не содержит `PriceElement`;
  при необходимости автор шапки выровняет её сам.
- Влияние на таблицы вне `JoinBorderedTable` (MVC-страницы портала, `JoinTableSimple`).

## Решение

Новый файл изолированного CSS `src/Common/WebComponents/JoinRpg.Common.WebComponents/JoinBorderedTable.razor.css`:

```css
::deep td:has(> .price-value) {
    text-align: right;
}
```

- `::deep` — потому что `<td>` рендерится в шаблоне вызывающего компонента
  (`ItemTemplate`), а не внутри самого `JoinBorderedTable`.
- `:has(> .price-value)` — детект по классу, который ставит `PriceElement`;
  класс остаётся обычным атрибутом независимо от CSS-изоляции.
- `:has()` поддерживают все современные браузеры (с 2023), проект на современном
  стеке (Blazor islands, ASP.NET Core 10).

## Рассмотрено и отвергнуто

- **Явный класс на `<td>`** (как в `RoomTypeListRow`): требует правок во всех
  местах использования и дисциплины у будущих авторов — пользователь выбрал
  автоматический вариант.
- **Правило в общем `site.css` портала**: не распространяется на изолированный CSS
  Blazor-компонентов и на других потребителей пакета `JoinRpg.Common.WebComponents`.

## Проверка

- `dotnet build` — файл CSS подхватывается сборкой RCL.
- `dotnet test src/JoinRpg.Common.WebComponents.Test` — существующие тесты
  `JoinBorderedTable` зелёные (поведение разметки не меняется; стили bUnit не вычисляет).
