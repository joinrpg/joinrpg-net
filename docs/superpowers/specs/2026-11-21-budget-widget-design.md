# Виджет «Бюджет Joinrpg» на /about — дизайн

Дата: 2026-11-21
Статус: предложено (одобрен мокап, ожидает старт реализации)

## Зачем

Joinrpg — открытый проект, который живёт на донаты. На странице `/about` в панели
«Как помочь?» сейчас есть только призыв поддержать проект. Хочется показать
прозрачность: сколько пришло и сколько потрачено по бюджету проекта за последние
завершённые периоды — чтобы потенциальный донор видел, куда идут деньги.

## Цели

- Виджет в панели «Как помочь?» на `/about`, показывающий по бюджетному проекту
  три цифры — доход, расход, итог (доход − расход) — за пять периодов:
  1. Три последних завершённых календарных месяца.
  2. Текущий год (с начала года, без верхней границы).
  3. Последний полностью завершённый год.
- Периоды считаются автоматически от текущей даты, никакой ручной настройки.

## Не-цели

- Детализация внутри периодов (по категориям расходов, по операциям) — не делаем.
- Графики, диаграммы, интерактив — статичный пререндер, без WASM-интерактива.
- Виджет не показывается нигде, кроме `/about`.
- Настройка состава периодов (число месяцев и т.п.) — не делаем.

## Анти-цели

- Не дублировать бухгалтерию: это информативная сводка, а не официальный отчёт.
- Не выводить русские строки из сервисного/доменного слоя (все UI-строки — в Web-слое, на русском).
- Не читать данные напрямую из БД со страницы — только через репозитории и сервисы.

## Данные

Бюджет ведётся в обычном проекте joinrpg, id которого указан в конфигурации,
секция `"Budget"` (`BudgetOptions.Project`, `src/JoinRpg.Interfaces/BudgetOptions.cs`,
уже существует в master — тот же проект, что используется для пожертвований).

- **Доходы** — все одобренные финансовые операции проекта (`FinanceOperation`,
  `State == Approved`). Суммируются **все** `MoneyAmount` за период: взносы и донаты
  положительные, возвраты отрицательные — поэтому возвраты корректно вычитаются
  из доходов. Дата операции — `OperationDate`. Нулевые суммы не читаются.
- **Расходы** — одобренные расходы (`Expense`, ADR030) с заполненным фактом:
  `State == Approved && ActualCost != null && SpentAt != null`. Дата расхода —
  `SpentAt` (дата, когда деньги реально потрачены). Одобренные без факта,
  неодобренные, без даты — не считаются.
- Деньги: доходы — `int` рубли (`MoneyAmount`), расходы — `decimal` рубли
  с копейками (`ActualCost`).

## Правила завершённости периодов

`today = DateOnly.FromDateTime(DateTime.Now)` на сервере, день цельный.

- Месяц `m` завершён, если `today >= 1 число следующего месяца + 15 дней`
  (то есть месяц закрывается с 16-го числа следующего).
- Год `y` завершён, если `today >= 1 января следующего года + 30 дней`
  (то есть год закрывается с 31 января).
- Текущий год — календарный год, следующий за последним завершённым.

Пример (`today = 2026-11-21`): месяцы — октябрь/сентябрь/август 2026,
текущий год — «С начала 2026», завершённый год — 2025.
В январе до 30-го числа «текущий год» и карточки месяцев относятся к разным
годам — периоды не должны пересекаться.

## Принятые решения (обсуждено)

1. **Доходы = сумма всех одобренных `MoneyAmount`, а не только положительных.**
   Возвраты (отрицательные суммы) вычитаются из доходов периода. Решение @leotsarev, 2026-11-21.
2. **Расходы = одобренный факт с датой** (`Approved + ActualCost + SpentAt`), дата периода — `SpentAt`.
   Плановые и неодобренные расходы в сводку не входят.
3. **Дизайн — карточки (вариант B v2)**: заголовок «Бюджет Joinrpg», строка из трёх
   карточек месяцев, строка из двух карточек годов; в карточке строки «Доход»
   (зелёный), «Расход» (красный), «Итог» (жирный, цвет по знаку). Групповых
   заголовков («Последние завершённые месяцы», «Годы») нет. Мокап:
   `artifacts/mockups/budget-widget-mockups.html`.
4. **Годовые карточки в порядке «С начала YYYY», затем «YYYY»** (текущий год первым).
5. **Виджет рендерится всегда** (конфиг `Budget` обязательный); у проекта без
   операций — нулевые суммы, без особых состояний «нет данных».

## Отвергнутые альтернативы

- **Доходы только `MoneyAmount > 0`.** Отвергнуто: возвраты внутри периода
  завышали бы доход. Суммируем все суммы (решение №1).
- **Отдельный options-класс под виджет.** Отвергнуто: `BudgetOptions` уже существует
  в master (переименован из `DonateOptions`, PR #6256) — переиспользуем его.
- **Групповые заголовки периодов** («Последние завершённые месяцы», «Годы»).
  Отвергнуто по требованию @leotsarev — минимализм мокапа.
- **Трактовка «с конца периода прошло N дней» как N дней после последнего дня.**
  Принята трактовка `>= первый день следующего периода + N дней` — иначе месяц
  закрывался бы только в середине позапрошлого месяца. Помечено в плане как
  решение на пересмотр при ревью.

## Как строим

По [docs/structure.md](../../structure.md), план — [2026-11-21-budget-widget.md](../plans/2026-11-21-budget-widget.md).

- **Data.Interfaces / Dal.Impl** — `IFinanceOperationsRepository.GetApprovedMoneyOperations(ProjectIdentification, DateOnly from)`
  и record `ApprovedMoneyOperation(DateOnly Date, int AmountRubles)`: все одобренные
  операции с `MoneyAmount != 0` начиная с даты. Расходы читаются существующим
  `IExpenseRepository.GetExpenses(ProjectIdentification)`.
- **Services.Impl** — чистый статический калькулятор `BudgetPeriods.For(DateOnly today)`
  (internal; 5 периодов: 3 месяца, YearToDate, CompletedYear, публичный enum
  `BudgetPeriodKind` в Services.Interfaces) + сервис `IBudgetWidgetService.LoadBudgetReport`
  → `BudgetReport`/`BudgetPeriodSums` (Kind, Start, Income, Expense). Сервисный слой
  строк не содержит — только числа и даты. Регистрация в `AddJoinDomainServices`.
- **WebPortal.Managers** — `BudgetWidgetManager.LoadWidgetModel(ProjectIdentification)`
  маппит отчёт в `BudgetWidgetModel` и формирует русские заголовки карточек
  («Октябрь 2026», «С начала 2026», «2025»).
- **Blazor.Client** — статический компонент `BudgetWidget.razor` + record'ы
  `BudgetWidgetModel`/`BudgetPeriodCard` в `CommonPages/`; параметр `BudgetWidget`
  у `AboutPanel`; суммы форматируются `"0.##"` + `₽` (ru-RU).
- **Portal** — `Pages/About/Index.cshtml.cs` инъектит `BudgetWidgetManager` и
  `IOptions<BudgetOptions>`, в `OnGet` собирает модель, передаёт в компонент
  через `param-BudgetWidget`, `render-mode="Static"`.

## UI

Все строки — на русском, в Web-слое.

1. Панель «Как помочь?» на `/about`: после текста про открытый проект и кнопок
   доната — заголовок «Бюджет Joinrpg» и карточки по мокапу. Названия месяцев —
   «Октябрь 2026» (месяц с заглавной), текущий год — «С начала 2026»,
   завершённый год — просто «2025».
2. Пустые периоды показываются как `0 ₽` — отдельных плейсхолдеров нет.

## Что оставлено исполнителю (мелочи)

- Точные сигнатуры репозитория и сервиса, разбиение razor-разметки.
- Юнит-тесты: `BudgetPeriods` (границы 15/30 дней, январская ситуация),
  `BudgetWidgetService` (возвраты вычитаются, операция на границе попадает
  в новый период, расход без факта/даты не считается, пустые данные),
  bUnit-тест компонента, тест менеджера. Интеграционные тесты локально не гонять.

## Открытые вопросы (звонки автора)

1. Переводы `TransferTo`/`TransferFrom` между мастерами тоже попадут в сумму
   доходов (они отрицательные/положительные пары и при внутренних переводах
   взаимно не сойдутся по периодам). В бюджетном проекте переводов быть не должно;
   если появятся — фильтрация по `OperationType` отдельной правкой.
2. Трактовка границы завершённости (с 16-го числа / с 31 января) — см.
   «Отвергнутые альтернативы»; при ревью плана подтвердить или скорректировать.
