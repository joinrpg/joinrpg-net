# Дизайн: ежемесячный финансовый отчёт в Telegram

Дата: 2026-11-22. Статус: предложение (утверждение пользователя обязательно до реализации).

## Зачем

Раз в месяц в канал Joinrpg отправляется отчёт о доходах и расходах — тот же, что виден
в виджете бюджета на странице /about. Сейчас публикация ручная/отсутствует, джоба автоматизирует.

## Что строим

Ежедневная джоба (`IJob`, планировщик AddMidnightJobs), которая по расписанию собирает
`BudgetReport` через `IBudgetWidgetService` (те же цифры, что на /about) и отправляет
отформатированное HTML-сообщение в Telegram-канал через `ITelegramNotificationService`.

## Расписание и канал — через конфигурацию

Новая секция конфигурации (отдельный options-класс рядом с `BudgetOptions`):

```json
"BudgetMonthlyReport": {
  "TelegramChatId": -1004315256401,
  "Schedule": "Daily"
}
```

- `Schedule: Daily` — отправлять каждый день (режим отладки, канал test_zovem_na_igru -1004315256401).
- `Schedule: Monthly` — отправлять только 16-го числа в 12:00 МСК. **16-е, а не 15-е**:
  месяц считается завершённым с 16-го числа следующего месяца
  (`BudgetPeriods.IsCompletedMonth`, src/JoinRpg.Services.Impl/Finances/BudgetPeriods.cs:42),
  именно тогда месяц начинает показываться на /about. Джоба стартует в 12:00 МСК
  (`[JobDelay(9)]`, полночь UTC + 9 ч), день проверяет сама — по образцу BudgetExpensesAlertJob.

Переключение на боевой канал (-1001560136215) и режим Monthly — только правка конфига
(appsettings.json / env-переменные в манифестах), без изменения кода. В appsettings.json
задефолтим отладочные значения (тестовый канал + Daily).

Отправка идёт стандартным ботом приложения (как все остальные отправки); доступ бота
к обоим каналам уже есть.

## Текст сообщения

Периоды берутся из `BudgetReport`: последний завершённый месяц (первый из Kind == Month)
и «с начала года» (Kind == YearToDate). Числа форматируются как в виджете ("#,0.##" ru-RU).
Итог: положительный — «…итого ХХХ рублей профицит», отрицательный — «…итого ХХХ рублей
дефицит». Telegram HTML: `<strong>/<em>/<a>` (другие теги не переживают санитайзер).

Пример (за октябрь 2026, отправка 16.11.2026):

> День добрый, хотим отчитаться о поступлениях и расходах за Октябрь 2026 года.
> Донаты и другие доходы ХХХ рублей, Хостинг и другие расходы ХХХ рублей, итого ХХХ рублей профицит.
> За весь 2026 год Донаты и другие доходы ХХХ рублей, Хостинг и другие расходы ХХХ рублей,
> итого ХХХ рублей профицит.
> Подробности можно узнать на joinrpg.ru/about/budget
> Подпись @joinrpg : принимаем донаты (https://joinrpg.ru/about/donate) : отвечаем в поддержке (https://joinrpg.ru/support)

## Страница /about/budget

Такой страницы сейчас нет — виджет бюджета живёт на `/about`. По решению пользователя:

- На странице About (Index.cshtml) добавить якорь `id="budget"` на блок виджета бюджета,
  чтобы ссылка `/about#budget` прокручивала к нему.
- Добавить Razor-страницу `/about/budget`, которая делает редирект на `/about#budget`
  (по образцу простых страниц About: отдельная .cshtml + PageModel с RedirectToPage).

## Устройство кода

- Джоба: `BudgetMonthlyReportJob` в `src/JoinRpg.Services.Impl/Finances/`, регистрация
  `.AddJob<BudgetMonthlyReportJob>()` в `Services.cs` рядом с `BudgetExpensesAlertJob`.
- Сборка текста — отдельный статический/internal метод построителя сообщения, чтобы его
  можно было юнит-тестировать без Telegram и БД.
- Тест: форматирование текста (месяц/год, профицит/дефицит) в `JoinRpg.Services.Impl.Test`
  по образцу `BudgetExpensesAlertJobTest`.

## Что вне рамок

- Мультибот/другой бот для канала (стандартный бот приложения).
- Отправка «15-го»: расписание привязано к логике виджета (16-е).

## Подходы

Рассмотрено: (1) конфиг-управляемый режим/канал — выбран пользователем; (2) захардкодить
канал и расписание с временным флагом в коде — отклонено: переключение требовало бы деплой.
Размещение джобы в JoinRpg.Services.Impl — единственный разумный вариант: там уже живут
BudgetExpensesAlertJob и BudgetWidgetService, `ITelegramNotificationService` доступен
через JoinRpg.Services.Interfaces без новых зависимостей.
