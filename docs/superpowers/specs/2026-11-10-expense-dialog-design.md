# Дизайн: форма добавления/редактирования расхода в диалоге

Дата: 2026-11-10

## Зачем

Сейчас форма расхода (`ExpenseEditForm`, `JoinRpg.Web.Finances`) вставляется панелью над гридом
и переводит страницу в «режим редактирования»: кнопки «Править»/«Потратил» в строках блокируются,
вёрстка прыгает. Диалог открывается поверх грида и этих проблем не создаёт.

## Цели

- Создание, правка и «Потратил» открываются в модальном диалоге.
- Поведение формы сохраняется: дефолты (дата, мастер), подстановка плана из факта,
  валидация, бейдж состояния при правке.
- Переиспользовать общий `JoinFormDialog`, не дублируя валидацию/кнопки.

## Нецели

- Менять сервисный слой (`IExpenseService`, реквесты), домен (`ExpenseCost`), грид,
  кнопки «Одобрить»/«Отклонить», экспорт Excel.

## Подходы

1. **`JoinFormDialog`, подстановка плана — обработчики `ValueChanged` полей факта (выбран).**
   В диалоге у «Цена (факт)» и «Количество (факт)» связывание через `Value`/`ValueChanged`:
   после ввода факта, если соответствующее плановое поле пустое, оно заполняется из факта.
   Для этого плановые поля модели становятся nullable и без значений по умолчанию — пустое
   поле честно отличимо от введённого. Никаких подписок на `EditContext`, `JoinFormDialog`
   и общие компоненты не меняются.
2. Свой диалог на голом `JoinDialog` со своим `EditForm` — отклонён: дублирует валидацию,
   кнопки и прогресс сабмита, которые `JoinFormDialog` уже умеет.
3. Добавить в `JoinFormDialog` параметр-колбэк после изменения поля — отклонён: не нужен,
   обработчики `ValueChanged` покрывают единственный сценарий «живого» поведения формы.

## Изменения

- Новый `ExpenseEditDialog` в `JoinRpg.Web.Finances/Expenses` — обёртка над
  `JoinFormDialog<ExpenseEditViewModel>`: заголовок «Новый расход»/«Редактирование расхода»,
  кнопки Add/Save, бейдж состояния, все поля через `FormRowFor`.
- `ExpenseEditViewModel`: `PlannedQuantity` → `int?` (без `= 1`), `PlannedPrice` → `decimal?`
  (без `= 0`). Валидация: `null` по плановым полям — ошибка «укажите количество/цену»
  (`[Required]` + проверки в `IValidatableObject.Validate`).
- `ExpensesPage.StartCreate`/`StartEdit` и контроллер (`ExpensesController`) адаптируются
  под nullable плановые поля; реквесты сервиса и сервис не меняются (контроллер достаёт
  значения через `!.Value` — валидная модель гарантирует их наличие).
- `ExpenseEditForm` удаляется.
- `ExpensesPage`: вместо подстановки панели — `await expenseDialog.ShowAsync(...)`;
  блокировки кнопок в строках (`Disabled="@(editing is not null)"`) убираются.
- Тесты `ExpensesPageTest` адаптируются под `<dialog>`: открытие по клику, сабмит кнопкой футера,
  закрытие через событие `onclose` (паттерн из `JoinFormDialogTest`).

## Мелочи (решение за исполнителем)

- `ValidationSummary` из старой формы не переносим: `JoinFormDialog` рендерит
  `DataAnnotationsValidator`, сообщения показываются по полям через `FormRowFor`.
- Дефолты модели (дата = последний расход, мастер = текущий пользователь) остаются в странице.
- Перед отправкой на сервер страница повторно применяет подстановку плана из факта
  (защита от потерянного change-события, как в старой форме).
