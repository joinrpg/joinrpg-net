# BrokenCharactersFilter в проблемах заявок

## Зачем

Зафиксировать инвариант: **проблемы утверждённой заявки всегда являются надмножеством
проблем персонажа** (заявочный грид из ADR027/#6097 показывает только заявочные проблемы,
поэтому персонажные проблемы не должны теряться).

Сегодня инвариант нарушает единственное место: `BrokenCharactersFilter`
(`src/JoinRpg.Domain/Problems/CharacterProblemFilters/BrokenCharactersFilter.cs`) —
Fatal-проблемы `NoParentGroup` и `GroupIsBroken` считаются только персонажным валидатором.

## Решения (принятые)

- **Для всех заявок**, не только утверждённых: без условий по статусу, симметрично
  персонажной стороне. Правило надмножества касается утверждённых и выполняется в любом случае.
- **`BlocksCheckIn` не включаем**: сломанная структура групп — работа мастера, останавливать
  check-in игроков она не должна. Остальные флаги уже безопасны по умолчанию:
  `VisibleToPlayer` = false (тест-страж `ClaimProblemVisibleToPlayerTest`),
  `IsAutoAcceptBlocker` = false, `PlayerCanFix` = false (чинит только мастер).
  Русские подписи уже есть в `ProblemViewModel.cs`.

## Как

- `BrokenCharactersFilter` реализует оба интерфейса: `ICharacterProblemFilter` и
  `IClaimProblemFilter`. Для стороны заявок берёт персонажа из `ClaimInfo.Character`.
- Регистрация в `JoinRpgDomainModule` через assembly-scanning подхватывает его автоматически,
  отдельной регистрации не нужно.
- Дублирования с полевыми проблемами нет: фильтр отдаёт только структурные типы.

## Проверка

- Новый юнит-тест в `JoinRpg.Domain.Test/Problems`: у утверждённой заявки на персонаже со
  сломанной группой проблемы заявки ⊇ проблемы персонажа (обе структурные Fatal есть
  в заявочном списке).
- Существующие тесты валидаторов продолжают проходить.
- `dotnet build`, `dotnet format --verify-no-changes --severity warn`.

## Не входит

- Судьба старого списка «Проблемные персонажи» и показ проблем персонажа в гриде — это
  открытый вопрос issue #6097, этим изменением не решается.
- Обновление текста issue #6097 и ADR013 (отвергнутый вариант 1 частично принят) — делается
  после влития.
