# ADR029: Вводная «сетка ролей»

Проблема
==

Вводные (сюжетные элементы) бывают только текстовыми: `PlotElementType { RegularPlot, Handout }`,
и у персонажа показываются лишь опубликованные `RegularPlot` как markdown-текст
(`CharacterPlotViewService.GetPlotForCharacters` жёстко фильтрует по типу).

При этом в [ADR008](adr008-roles-list-view-page.md) у настройки сетки ролей (`ProjectRolesList`)
заложен флаг `PublicMode` с семантикой «доступна публично **или только через вводные**» — но
механизма «сетка в вводной» не существует. Мастеру нечем показать игроку сетку ролей (например,
«список соседей по сюжету» или «кто есть в игре») в виде вводной: только публичной ссылкой,
которую игрок должен узнать изнутри игры.

Решение
==

Третий вид вводной — `PlotElementType.RoleGrid`: у персонажа вместо текста рендерится сохранённая
сетка ролей (`ProjectRolesList`). Решения (подтверждены автором проекта 2026-10-30):

1. **Ссылка на сетку — отдельное nullable-поле `PlotElement.ProjectRolesListId`** (int?), без FK
   и навигации — в отличие от `ProjectDetails.DefaultProjectRolesListId`, где ссылка на сетку
   сделана FK с навигацией. `ProjectRolesList` — настоящая EF6-сущность, но ссылку из вводной
   проверяем только в сервисе при сохранении (принадлежность проекту — через снапшот
   `ProjectInfo.GetRolesListByIdOrDefault`), на уровне БД её не ограничиваем. Сетки удаляются
   жёстко (`ProjectRolesListService.RemoveAsync`): FK без каскада блокировал бы удаление сетки,
   на которую ссылается вводная, а FK с `OnDelete = SetNull` требовал бы индекс на большой
   таблице `PlotElements` и связывал таблицы метаданных и сюжетов. Удалённая сетка → «Сетка ролей
   не найдена» на отображении, а не ошибка целостности.
2. **Приватная сетка (PublicMode = false) видна игроку через вводную.** Прямая ссылка
   `/{projectId}/roleslist/{id}` остаётся мастерской — проверка `PublicMode` в
   `ProjectRoleGridViewService` не меняется. Доступ к сетке в контексте вводной повторяет
   `AccessArguments.CharacterPlotAccess` (= `Published || PlayerAccessToCharacter || MasterAccess`):
   сетка публична, или у проекта включено «публиковать вводные» (`PublishPlot` — тогда сетку в
   вводной видит любой читатель, как текстовые вводные, в том числе после игры), или пользователь —
   мастер, или вводная опубликована и её таргеты (персонажи или группы — как при показе вводной на
   странице персонажа) пересекаются с персонажами, на которых у пользователя approved/checked-in
   заявка. Режим контактов сетки для игрока не понижается: если мастер вставил в вводную приватную
   сетку с `ContactsColumn = All`, игрок видит все контакты — мастер сам решил показать эту сетку,
   и билдер, как в ADR008, не зависит от того, кто на неё смотрит.
3. **Публикация — как у обычной вводной**: мастер создаёт, затем публикует (`Published` = номер
   версии); до публикации видна только мастеру. Текст пустой (`Content = ""`), версия 0 создаётся
   автоматически; ссылка на сетку не версифицируется — смена сетки у опубликованной вводной видна
   игроку без перепубликации (принятое упрощение).

Подробности
==

### Контракт и данные

- `PlotElementType.RoleGrid` добавляется **в конец** enum'а (значения персистентны числами:
  RegularPlot=0, Handout=1, RoleGrid=2). Зеркальный `PlotElementTypeView` — с русским
  `[Display]`-описанием.
- `PlotSpecification` (`IPlotRepository`) расширяется с одиночного `PlotElementType` до набора
  `IReadOnlyCollection<PlotElementType>` (совместный конструктор для одиночного типа — все
  существующие вызовы не меняются). Выборка персонажа берёт `[RegularPlot, RoleGrid]`. EF6 не
  всегда корректно транслирует `Contains` по набору enum в дереве выражений — в предикате
  надёжнее явное `type == RegularPlot || type == RoleGrid`, покрыть интеграционным тестом.
- `PlotTextDto` не несёт ни типа, ни ссылки — добавляются `ElementType` и `RolesListId`;
  в `PlotElementDetailsDto` `ElementType` уже есть, добавляется только `RolesListId`. Далее по
  цепочке `PlotRenderer` → `PlotRenderedTextViewModel` (+ имя сетки из `ProjectInfo` для заголовков).
- Миграция EF6: колонка `PlotElements.ProjectRolesListId` (nullable int); обновить
  [db-schema.md](db-schema.md) тем же PR (иначе красный `DbSchemaDocumentationScenario`).

### Создание и редактирование

- Тип выбирается при создании (как сейчас); в форме (`PlotElementEditPanel`) для RoleGrid —
  селектор сетки по образцу `PlotFolderSelector` (список сеток — новый read-only метод
  `IPlotClient.GetRolesListsList` поверх `ProjectInfo.ProjectRolesLists`), без текстового редактора.
- `PlotService.CreatePlotElement/EditPlotElement` валидируют: RoleGrid без сетки — ошибка;
  сетка чужого проекта — not found; сетка у не-RoleGrid типа — ошибка. Контент игнорируется.
- Клонирование: `CloneProjectHelper` копирует сетки (`CopyRolesLists`) **до** сюжетов (`CopyPlot`),
  но маппинга id сеток сейчас не строит — его надо добавить в `CopyRolesLists` и применить в
  `CopyPlot`. Клон не опубликован — общее поведение `CopyPlot` для всех вводных.

### Отображение у персонажа

- `PlotElementsView` (страница персонажа, карточка заявки) для RoleGrid рендерит заголовок
  «Сетка ролей: {имя}» и вложенный `ProjectRoleGrid`. Это **композиция внутри одного острова**,
  не второй остров: `PlotElementsView` выполняется в WASM-приложении `JoinRpg.Blazor.Client`, где
  `IProjectRoleGridClient` уже зарегистрирован; серверный пререндер отрисует грид через серверную
  реализацию сервиса. Для этого — ссылка `JoinRpg.Web.Plots → JoinRpg.Web.CharacterGroups`
  (перекрёстные ссылки Web.*-проектов уже есть, например AdminTools → Games; цикла нет —
  CharacterGroups не ссылается на Plots).
- Данные вложенная сетка берёт отдельной ручкой `/webapi/project-role-grid/getforplot`
  (`GetRoleGridForPlot(PlotElementIdentification)`), которая и выполняет проверку доступа из п.2:
  `PublicMode` сетки, `PublishPlot` проекта, права мастера или пересечение таргетов вводной с
  персонажами пользователя (новый метод `IClaimInfoRepository.GetApprovedClaimCharacterIds` —
  персонажи approved/checked-in заявок; пересечение — `TargetsInfo.HasIntersections`, покрывает и
  групповые таргеты). Неопубликованная или `IsMasterOnly` вводная игроку не отдаётся.
- Уведомление о публикации: шаблон письма уже содержит ссылку «Прочитать её: %recepient.claim%#pe{id}»
  (карточка заявки, где сетка и отрендерится) — прямую ссылку на `/roleslist/{id}` в письмо не давать:
  приватная сетка игроку по ней не откроется. Для RoleGrid в текст письма дописывается имя сетки.
- `ReorderPlotByChar` (персональный порядок `PlotElementOrderData`) расширяется на RoleGrid,
  иначе move-контрол на странице персонажа сломается.

### Печать

Печать использует **тот же компонент `ProjectRoleGrid`**, подготовленный к печати: параметр
`PrintMode` прячет интерактив (меню редактирования групп, фильтр ролей, тултипы), рендер —
`Html.RenderComponentAsync<ProjectRoleGrid>(RenderMode.Static, …)` в печатной вьюхе. Статический
рендер не гидратируется в WASM — это чистый HTML; данные компонент берёт через серверную
реализацию `IProjectRoleGridClient` (уже зарегистрирована), рендер дожидается `OnInitializedAsync`.
Ограничение: JS-интероп компонентов обязан жить в `OnAfterRender*` (при статическом рендере не
выполняется) — аудит в начале PR; если Static-рендер упрётся, откат на Razor-partial локален,
печать — последний PR стека. Разметку сетки не дублируем: экран, печать и будущие фичи сетки —
одна реализация.

Две точки печати:

1. **Вводная у персонажа** — `PrintCharacter.cshtml` для RoleGrid-вводной вставляет компонент
   статически (доступ — как у всей печати персонажа, мастер). Каждая вводная печатает свою сетку;
   при массовой печати повторение одной и той же сетки допускаем сознательно (одна сетка у
   нескольких персонажей — редкий случай).
2. **Страница сетки, вне вводных** — тонкая печатная страница в печатном layout для сохранённой
   сетки (`/roleslist/{id}`) и классической (`/roles/{groupId}`) + кнопка «Печать» на странице
   сетки. Доступ повторяет страницу сетки (`PublicMode`/мастер, классическая публична), данные —
   те же ручки `Get`/`GetClassic`. Благодаря переиспользованию компонента страница почти
   бесплатна: ни строчки разметки сетки не дублируется.

Печать рассчитана на компактные сетки; гигантские сетки из замеров ADR011 (19 609 строк) на
бумагу не выводятся — это ограничение здравого смысла, а не механизма.

Что не делаем
==

- FK/навигация `PlotElement → ProjectRolesList` (голый `int?`, см. п.1).
- Изменение публичной страницы `/{projectId}/roleslist/{id}` и её проверки `PublicMode`.
- Версионирование ссылки на сетку (смена сетки не плодит версии, см. п.3).
- Оптимизации payload из [ADR011](adr011-roles-grid-payload.md): несколько RoleGrid-вводных у
  одного персонажа = несколько полных загрузок сетки (каждая — отдельный запрос `GetForPlot`),
  и каждая сетка запрашивается дважды за просмотр (пререндер серверной реализацией + повторный
  HTTP из WASM — `PersistentComponentState` в `ProjectRoleGrid` сейчас ничего не сохраняет);
  если persisting починят, ключ состояния надо различать по id сетки, иначе несколько сеток на
  странице будут получать данные друг друга. Вернёмся к этому в рамках ADR011, если станет
  заметно на больших играх.
- Handout-пути (чекин, отчёт по раздатке, XGameApi) — не затрагиваются.

Реализация
==

Стек PR, каждый самостоятельно собирается и зелёный; в скобках — от чего зависит. Две ветки
стека независимы: контур фичи (PR 1–4, 6) и подготовка печати (PR 5) идут параллельно.

1. **Контракт и данные** — enum, поле + миграция + db-schema.md, `PlotSpecification` → набор,
   DTO-поля и проекции, бейджи/отображение типа. Поведения для пользователя не меняет.
2. **Создание/редактирование** *(← 1)* — сервисы и валидация, селектор сетки, ветка формы,
   клонирование, мастерская панель (имя сетки + ссылка), имя сетки в письме о публикации.
3. **Доступ через вводную** *(← 1; параллелен 2)* — `GetApprovedClaimCharacterIds`,
   `GetRoleGridForPlot` + ручка + HTTP-клиент, параметр `AccessViaPlotElement`
   у `ProjectRoleGrid`.
4. **Отображение у персонажа** *(← 3)* — ссылка csproj Plots → CharacterGroups,
   `PlotRenderer`/VM, ветка RoleGrid в `PlotElementsView`, `ReorderPlotByChar`.
5. **Печать сетки: подготовка компонента** *(не зависит от 1–4)* — `PrintMode`
   у `ProjectRoleGrid`, аудит JS-интеропа под статический рендер, печатная страница сохранённой
   и классической сетки, кнопка «Печать» на странице сетки. Самостоятельное улучшение
   существующей сетки, мерджится независимо от фичи вводной.
6. **Печать вводной** *(← 4 + 5)* — печать RoleGrid-вводной в `PrintCharacter.cshtml`.
