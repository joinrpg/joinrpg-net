# ADR023: Статус проекта «Заблокирован» на время восстановления данных

Проблема:
==

Прод-MSSQL потеряна, основная БД восстанавливается из майского бэкапа (DRP #5459). Данные активных
проектов за сезон восстанавливаются по частям, для каждого проекта в своём темпе. Пока это идёт,
проект нельзя менять обычным образом: правки игроков и мастеров поверх майских данных смешаются с
восстанавливаемыми. Ждать восстановления всех проектов, чтобы открыть сайт, — слишком долго (#5473).

Сейчас у проекта три состояния (`ProjectLifecycleStatus`): приём заявок открыт, закрыт, архив.
`ProjectInfo.IsActive` значит «не в архиве» и отвечает сразу на два разных вопроса:

- **можно ли менять** проект — `ProjectActiveRequirement`, `EditAllowed` в аргументах доступа,
  кнопки правки;
- **как его показывать** — сокращённые контакты и экспорт, отдельный список архивных проектов,
  «работа по заявке остановлена» не считается.

Для архива ответы совпадают, для заблокированного — нет: менять нельзя, а показывать надо как
активный.

Решение:
==

1. **Флаг `Project.IsBlocked`** рядом с `Active` и `IsAcceptingClaims`; их блокировка не трогает,
   поэтому после снятия проект возвращается ровно в прежнее состояние, включая открытый приём заявок.
   `ProjectLifecycleStatus.Blocked` вычисляется из флага при загрузке (`ProjectLoaderCommon.CreateStatus`).
   Заблокировать можно только активный проект. SQL-фильтры по `Project.Active` для списков не
   меняются: заблокированный в списках — активный.

2. **«Не в архиве» и «можно менять» — разные свойства.**
   - `ProjectInfo.IsActive` / `ProjectLifecycleStatus.AllowsChanges()` — проект можно менять обычными
     операциями. Блокировка → `false`.
   - `ProjectInfo.IsArchived` / `ProjectLifecycleStatus.IsArchived()` — вопросы чтения.
     Блокировка → `false`.

3. **`ProjectActiveRequirement`** (ADR009) заявляет, при каких состояниях операция допустима:

   | Требование | Архив | Блокировка | Примеры |
   |---|---|---|---|
   | `MustBeActive` | нет | нет | почти всё |
   | `AllowArchived` (бывший `AllowInactive`) | да | нет | комментарии к заявкам (ADR014), публикация |
   | `AllowBlocked` | нет | да | выдача и правка прав мастеров, снятие блокировки, закрытие, инструменты восстановления |
   | `AllowArchivedOrBlocked` | да | да | снятие мастера, профиль мастера, порядок мастеров |

   Снять мастера, у которого есть заявки, в заблокированном проекте нельзя — как и в архиве: заявки
   перед снятием передаются другому мастеру через `SetResponsible`, а это операция над заявкой
   (`MustBeActive`), и переносить её внутрь операции над проектом значит выйти за границу агрегата
   (ADR014).

   В заблокированном проекте запрещено всё, кроме ACL мастеров, снятия блокировки, закрытия и
   инструментов восстановления; в том числе комментарии, форум, оплаты и подписки.

4. **Выход** — снять блокировку или закрыть проект. Оба действия доступны мастеру с
   `CanChangeProjectProperties` и администратору и означают, что восстановление закончено. Ставит
   блокировку только скрипт DRP; кнопки «заблокировать» в UI нет.

5. **Джобы** не выбирают заблокированные проекты вовсе — иначе они упадут на проверке активности.
   Прежде всего `ProjectPerformCloseJob`: он не предупреждает и не закрывает заблокированный проект.

6. **Видимость**: метка статуса в меню и списках, плашка «Проект заблокирован на время
   восстановления данных» на странице проекта, своя страница ошибки при попытке изменения
   (`ProjectBlockedException`, наследник `ProjectDeactivatedException`).

План:
==

| PR | Что |
|---|---|
| 0 | Этот ADR; `IsArchived`/`AllowsChanges`, места чтения переведены на `IsArchived`, `AllowInactive` → `AllowArchived`. Поведение не меняется |
| 1 | `Project.IsBlocked`, `ProjectLifecycleStatus.Blocked`, требования `AllowBlocked`/`AllowArchivedOrBlocked`, `ProjectBlockedException`, отказ в подаче заявки |
| 2 | Проверки в сервисах без них (форум, оплаты, переводы, подписки, КогдаИгра), фильтры джоб |
| 3 | Снятие блокировки, закрытие из блокировки, плашка, метки, кнопки |
| 4 | DRP: скрипт блокировки — в плане `docs/drp-2026-10-mssql-loss.md` (PR #5459) |

Что не делаем:
==

- Дату «последнего обновления» при снятии блокировки не трогаем: проект, который разблокировали без
  восстановления, `ProjectPerformCloseJob` закроет штатно.
- Уведомлений о блокировке и снятии нет — мастерам сообщает коммуникация DRP. Закрытие
  заблокированного проекта шлёт обычное письмо о закрытии.
- Блокировку как постоянный механизм (модерация, заморозка за нарушения) не проектируем: статус
  нужен на время одного инцидента.
